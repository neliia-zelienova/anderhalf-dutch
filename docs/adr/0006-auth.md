# Context 
App should provide user verification and authentication and provide the security for users data. Login and signing in is provided by magic link. One web client, one domain, no external auth services.

# Decision
Sessions stored in DB. HTTP only, no passwords, Secure, session lives 14 days, 3 inactive days, @nestjs/authentication. Cookie holds a random token, DB stores only its hash

# Alternatives
JWT token rejected. Handy with lots of services and mobile client (which is not a prio now). Token saved in localStorage could be stolen by XSS. Cannot be revoked until expiration.
Passwords hashed with bcrypt/argon2 rejected. Requires saving secrets, add password reset.
Auth0/Clerk rejected. External dependency, not a good space for learning   

# Consequences
+ remove all users sessions from all devices with one click by removing them from the DB table
+ simple and secure flow. HttpOnly cookie is not reachable from JS, so XSS will not steal it 
- requires calling DB for user check
- entry depends on mail delivery (SMTP)
- same device login - a link works only in the browser that requested it
- any email could be registered, rate limit is a guard against abuses
- @nestjs/authentication version 0.x. Could change in future
